# SkyNet Pocket enrollment and authenticated uplink

Target: the original ESP32E N4 CYD / ESP32-2432S028R with 2.8-inch ILI9341. Confirm board revision and preserve a flash backup. The GOOUUU ESP32-S3 is a separate target; never flash it with CYD images.

The initial architecture specified a non-exportable asymmetric device signing key. That stronger hardware-anchored identity design is **not** implemented on the baseline CYD. Draft PR #12's optional HTTPS telemetry uplink uses a *software-stored*, random, unique 256-bit HMAC-SHA256 key, provisioned onto the CYD via the password-protected local setup AP, and registered by an authorized operator on a separate gateway. NVS without flash encryption is extractable by an attacker with device access; **do not call this hardware-attested identity**.

The operator must retain a real consent reference and expiry in the private gateway registry before enabling a device. Each heartbeat signs the request method, exact path, device ID, timestamp, random nonce, and SHA-256 of the exact JSON body. The gateway verifies the HMAC using the registered secret, restricts clock skew to ±300 seconds, persists nonce uniqueness across restarts in SQLite, enforces a 1,024-byte schema limit, and accepts only devices with active consent. The CYD must validate the TLS certificate using its configured CA trust anchor, and must not use `setInsecure()` or include a GitHub API token.

Only a local network status summary (uptime, Wi-Fi RSSI, S3 JSON endpoint reachability and RuView JSON endpoint reachability) can be uploaded. A gateway ACK proves a software credential signed an accepted payload; it does **not** independently verify physical board identity, CSI capture, people detection, location or live camera origin.

GitHub Pages can display operator evidence but cannot accept the device's uploads. The receiver runs on a separately managed, authenticated HTTPS gateway with public DNS; the Python process itself listens on loopback behind a TLS proxy. Operator read-only status and receipt routes require a separately held bearer token. Receipts are subject to freshness and bounded retention. Follow the [Pocket uplink runbook](pocket-uplink.md) for exact setup, security limits, testing, revocation and rollback.

**Release gates:** Python tests passed, CYD PlatformIO build passed, signed device receipt in the exact remote gateway, live freshness, valid participant consent evidence, local hardware logs and independent Red/Blue review are *separate* milestones. Do not promote the first two to production acceptance. Future secure-element/flash-encrypted asymmetric enrollment may improve identity assurance only after its own hardware validation.
