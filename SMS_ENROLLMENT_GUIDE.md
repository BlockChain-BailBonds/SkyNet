# SkyNet v0.5 — SMS invitation and voluntary mobile sensor enrollment

**Intellectual property by Matthew Blake Ward, in association with 918 Technologies.** This attribution covers original project work, not RuView or third-party mapping/software/data.

## What is implemented

SkyNet's operator map creates a target-zone invitation, which the operator can put in a text message. The invitation is a one-use, 15-minute bearer link, generated by an authorized backend. **Open SMS app** invokes the device's messaging application with a prefilled message. The operator reviews and presses Send. If no messaging application is available, **Copy text + link** permits manual transmission. **No SMS delivery is claimed or sent by the gateway.** A provider account would be needed for unattended outbound SMS.

The invitee follows `/join#invite=<opaque-token>` on a public HTTPS domain and reads what will be collected. The invitee must check four consent declarations and tap **Agree & start sensor**. Only then does the browser request motion and location permissions. The server checks a one-time self-reported location (accuracy no worse than 100 m, and position plus accuracy within the 100–500 m site radius). The backend does not persist the exact coordinate. It creates an ephemeral session lasting at most 30 minutes. The browser uploads **only aggregated motion RMS, sample count and heartbeat approximately every four seconds**; it never uploads raw motion measurements, GPS trails, images, audio or Wi-Fi CSI.

**Stop sharing now**, closing/leaving the page, or switching away terminates sensor collection. Browser page-exit revocation is best effort; on lost connectivity the server stops treating the heartbeat as active after 16 seconds. Sessions eventually expire even if the stop request is lost. The operator can request a status count for the specific site using an admin token. Site status and RuView hardware readiness are *separate* fields.

**Limitations:** Browser device-motion APIs vary. Some phones/browsers deny these permissions, do not emit events or suspend them when the page sleeps. The recipient's phone does *not* become a Wi-Fi CSI receiver and does not sense others at the address. Its reported location can be spoofed; the location check is not independently verified. A text message does not establish consent or identity. RuView needs compatible, deployed, physically verified Wi-Fi hardware at that site. An ordinary phone cannot see inside buildings, through walls or into arbitrary distant areas by opening a web link.

## Local operator setup

Use Python 3.10+ on the SkyNet host. Generate a random operator token (never share it with volunteers):

```bash
cd 918_skynet_ruview
export SKYNET_ADMIN_TOKEN="$(python3 -c 'import secrets; print(secrets.token_urlsafe(32))')"
export SKYNET_PUBLIC_URL='https://skynet.example.com'
python3 server.py
```

Replace `skynet.example.com` with **your own operational DNS hostname**, with a valid TLS certificate and an HTTPS reverse proxy. The example domain is not a live SkyNet service. Only HTTPS public origins are accepted. By default the Python gateway binds to `127.0.0.1:8787` and should stay private; use a reverse proxy on the same host for the public consent routes.

Open the **operator dashboard locally** at `http://127.0.0.1:8787` or via an authenticated private tunnel. Choose an address or map location, open **SMS sensor invitations**, enter the admin token, optional mobile number and optional actual RuView node IDs. Generate an invitation, tap **Open SMS app** from a compatible device, or copy the SMS content on a desktop. Never paste the admin token into the outgoing message. Each one-use link expires after 15 minutes; if the target coordinate changes, generate another.

### Public HTTPS proxy (Caddy example)

With DNS set to the proxy host and Caddy installed on the same machine, configure a Caddyfile similar to:

```caddyfile
skynet.example.com {
    @enrollment path /join /join.html /api/enroll/info /api/enroll/start /api/enroll/sample /api/enroll/stop
    handle @enrollment {
        reverse_proxy 127.0.0.1:8787
    }
    handle {
        respond "Not found" 404
    }
}
```

**Important:** The operator routes (`/`, `/api/sites/*`, `/api/ruview`, `/api/scan`, `/api/evidence`, `/api/config`) should NOT be exposed to the public internet through this proxy. Keep all local RuView access private. Put abuse prevention, request rate limits, IP/log privacy controls, TLS hardening, and consent-policy review in place before real deployment. SMS is not encrypted, link recipients can forward links, and a one-time token must be treated like a password until redeemed. Any public proxy logs must not retain enrollment tokens or precise GPS payloads.

### If you only have the HTML file

`SkyNet_918_Interactive_Google_Maps.html` can display the map standalone, but **it cannot create real invitations without its Python backend**. The mobile consent view is served as `static/join.html` by the gateway. A `file://` page or a loopback URL sent by SMS is not accessible to another phone. A public HTTPS endpoint is mandatory for SMS enrollment on distinct devices.

## Site status definitions

- **UNVERIFIED**: an invitation was generated but has no confirmed SMS delivery, or RuView self-reports node IDs that do not prove physical installation.
- **BLOCKED**: missing operator token, missing public HTTPS origin, invalid/expired link, absent permissions, no adequate location, or no fresh RuView frames.
- **ACTIVE VOLUNTEER MOTION**: a consenting phone is streaming summarized accelerometer readings. This *does not* indicate any other person's presence.
- **VERIFIED**: only a directly observed and independently reproduced source fact; do not promote site occupancy or device hardware acceptance on the basis of map pins or self-reported phone position.

## Local test

```bash
python3 -m unittest discover -s tests -v
node --check /tmp/skynet_index.js
node --check /tmp/skynet_join.js
```

The project automated suite tests token expiration, one-use redemption, separate sensor streams, revocation, geofence validation, authorization and HTTP routes. For syntax tests, extract each inline `<script>` to a temporary `.js` file before running `node --check`. A real two-phone HTTPS + carrier-SMS + physical RuView test is still required for hardware and delivery acceptance.
