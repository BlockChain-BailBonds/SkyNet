Independent HTTPS / WSS gateway

Operator configured

Read-only GET and WebSocket handshake. No telemetry is sent. Cross-origin requests require gateway CORS support. The bearer token is cleared immediately after each HTTPS check and is never used for WSS.

SkyNet Pocket / ESP32 evidence

Consent & authenticated status

Hardware acceptance separate

The repository documents /api/sites/status for consenting phone-motion sites, which are not ESP32 Pocket nodes. API availability alone does not establish consent, physical location, or an enrolled device.

Required consent record

Scope, operator/site identity, opt-in timestamp, validity period, withdrawal/revocation mechanism, retention policy and permission to transmit. A copied invitation URL is not proof of continuing consent.

Pocket gateway receipts

No endpoint assumed

Enter real, documented read-only routes from your running gateway. The repository does not establish a production device or receipt API, so none is guessed.

What counts as direct device evidence?

Exact board ID and firmware hash, enrolled public-key registration, signed nonce/timestamp acceptance, replay verification, consent ID, gateway receipt ID, and fresh heartbeat linked to that device. Camera/CSI/RuView sensing additionally needs physical capture/calibration logs.

Evidence boundaries

Public probes may return VERIFIED for HTTP transport or a GitHub workflow only. They cannot prove signed device receipts, non-simulated CSI, camera capture, actual RuView measurements, calibration or location-specific detection.

This dashboard performs no flashing, provisioning, enrollment, network scanning, SMS sending, mutation to GitHub, deployment trigger or telemetry upload. Any operator-supplied authentication is sent only to the selected HTTPS origin.
